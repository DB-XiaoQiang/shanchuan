# 独立 macOS 更新测试通道

本通道用于手动验证专用测试应用从 **0.1.3** 更新到 **0.1.4** 的发现、下载、验签、确认安装及重启流程。它不是原版 0.1.3 中已经存在的开关，也不把现有公开预发布改为正式版本。

两个测试包由同一代码快照构建、使用不同测试版本和递增构建号，均明确标注独立测试。它们不会替代 `/Applications/闪传.app` 中日常使用的原始版本。

## 应用与数据隔离

- 应用名称：`闪传更新测试.app`。
- Bundle ID：`local.copytool.update-test`，与日常闪传不同。
- 测试标记：`ShanchuanUpdateTest=true`；两份包都固定 `ShanchuanUpdateTestTargetVersion=0.1.4`。
- 测试应用使用独立 `CopyToolUpdateTest` 数据目录，运行配置禁止普通 FTP、全局发送快捷键和原应用迁移。
- 测试发行公钥与 Sparkle 公钥均独立生成，不接受正式公钥，也不读取正式 FTP 密码。
- 发现源与 Sparkle appcast 固定使用新测试预发布 `update-test-v0.1.4`；现有 `v0.1.4` 及其附件保持不变。

测试包使用本机稳定代码签名身份，不代表通过 Developer ID 正式发行签名或 Apple 公证。正式通道保持关闭。

## 构建两份测试应用

先在外部临时目录生成独立的 P-256 发行密钥与 Sparkle Ed25519 密钥。工具仅输出结果说明，私钥文件权限为 0600，不读取生产密钥或写入钥匙串；完成测试发行签名后可删除临时私钥。私钥不传入打包脚本，也不会进入应用、ZIP 或源码。

```sh
TEST_KEYS_DIR="$(mktemp -d /tmp/shanchuan-update-test-keys.XXXXXX)"
swift scripts/update-test-release.swift keys "$TEST_KEYS_DIR"
```

```sh
./scripts/package-update-test.sh \
  --version 0.1.3 --build-number 1003 \
  --manifest-public-key "$TEST_KEYS_DIR/manifest-public-key.pem" \
  --sparkle-public-key "$TEST_KEYS_DIR/sparkle-public-key.txt"

./scripts/package-update-test.sh \
  --version 0.1.4 --build-number 1004 \
  --manifest-public-key "$TEST_KEYS_DIR/manifest-public-key.pem" \
  --sparkle-public-key "$TEST_KEYS_DIR/sparkle-public-key.txt"
```

`COPYTOOL_SIGNING_IDENTITY` 可显式指定签名身份；未提供时，脚本要求本机只有一个可用的 Apple Development 身份。两份包必须使用相同身份与相同测试公钥。构建号必须递增：Sparkle 根据 `CFBundleVersion` 判断能否升级，不能把两份包都设置为 `1`。

默认输出目录为 `dist/update-test/<版本>/`，包含测试应用、`ShanchuanUpdateTest-macos-arm64.zip` 及不含私钥的构建说明。输出目录已存在时拒绝覆盖，可用 `--output` 指定新的空目录。脚本不修改仓库 `VERSION`、`RELEASE_CHANNEL`、正式公钥或正式安装包，不启动任何 GUI 应用。

## 发布与手动验收

发布准备步骤应对 **0.1.4 测试 ZIP 的最终原始字节**生成 Sparkle 签名，再生成测试 appcast、包含包大小与 SHA-256 的发行清单及其 P-256 签名。测试清单使用 `channel=test`，只有专用测试应用接受；生产应用继续只接受正式通道。

```sh
swift scripts/update-test-release.swift release "$TEST_KEYS_DIR" \
  "dist/update-test/0.1.4/闪传更新测试.app" \
  dist/update-test/0.1.4/ShanchuanUpdateTest-macos-arm64.zip \
  dist/update-test/release
```

发行工具检查 Bundle ID、测试标记、目标版本、构建号及两种内置公钥，然后才生成新发行目录；已有输出拒绝覆盖。ZIP 签名可再使用 Sparkle `sign_update --verify --ed-key-file` 和应用公钥核验；私钥不进入任何上传文件。

发布时只创建独立测试预发布 `update-test-v0.1.4`，上传目标测试 ZIP、`appcast.xml`、`update-manifest.json` 和 `update-manifest.sig`。不覆盖现有 `v0.1.4` 的附件或校验文件。

初次安装 0.1.3 测试应用时，通过 Finder 或 macOS LaunchServices 启动，核对明显的测试标识与版本。手动检查后，应发现 0.1.4；下载和验签结束后由用户确认安装，最终启动同一测试 Bundle ID 的 0.1.4。测试应用的配置与缓存独立，正式闪传及其 FTP 设置不参与此过程。

若希望由用户亲自触发首次发现/下载，可在测试发行尚未发布时先启动 0.1.3 测试应用，等无更新检查完成后正常退出；发布测试附件后再打开测试应用。本日窗口已完成，不会在启动时先行下载，用户点“检查更新”会立即重新请求。不得预置已下载候选包来代替网络发现验证。
