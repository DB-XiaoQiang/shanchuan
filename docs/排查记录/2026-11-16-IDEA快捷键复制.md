# IDEA 快捷键复制被取消的排查

## 现场与复现

用户使用 macOS 0.2.1，在 IDEA 中完整按下、松开 Control+Option+C，部分请求显示“等待快捷键释放期间检测到新的操作，未发送”。同一时段也有复制确认及 FTP 上传成功记录，失败发生在上传之前。

失败日志中，HID 的 keyDown 累计计数增加 1，鼠标按下和滚动计数没有变化。原实现据此认为用户又执行了一次操作。

使用独立只读 Carbon 探针注册 Control+Option+Shift+C，用户实际完整按下、松开三次。探针不读取剪贴板、不发送按键、不连接 FTP。结果：

| 通知 | 配置主键状态 | HID keyDown 计数 |
| --- | --- | --- |
| 第一轮按下 | 已按下 | 28730 |
| 第一轮松开后 100 ms | 已松开 | 28730 |
| 第二轮按下 | 已按下 | 28731 |
| 第二轮松开后 100 ms | 已松开 | 28731 |
| 第三轮按下 | 已按下 | 28732 |
| 第三轮松开后 100 ms | 已松开 | 28732 |

`secondsSinceLastEventType` 同样仍指向先前事件。已确认本机累计活动统计并非与 Carbon 回调同步更新，不能把迟到的累计计数直接解释成授权之后的新操作。该观测不代表 Apple 对所有系统版本给出了固定延迟保证。

原始采样只保存在本地 `evidence/shortcut-20261116/`，不随发布包分发。

## 修复约束

- 不容忍任意 `keyDown +1`，不在等待松键后重新授权输入窗口。
- 主键和修饰键都松开后才分发复制；Carbon 的组合释放通知本身不等同于完整物理松键。
- 跨应用请求使用仅在该操作期间存在的输入保护；不记录键值或字符。保护不可用、失效或超时时取消操作。
- 同一次请求固定输入代次，等待、菜单分发、按键回退和剪贴板确认始终使用它。新输入优先于剪贴板变化取消发送。
- 注册快捷键首次按下时就准备观察，释放时复用同一实例；不在释放后重新建立授权基线。长按自动重复只去重，下一次独立按下仍取消旧请求。
- 本应用内使用派发前的本地事件监控，保持无需额外辅助功能授权即可操作自身控件。
- 剪贴板仍须在已分发复制之后的一秒窗口内更新，读取方继续在冻结内容前后校验 changeCount。

## 验收边界

真实键盘已复现统计延迟。单元测试、注册探针和打包验证用于检查实现；修复构建仍需实际 IDEA 复制验收。真实 FTP 仅在用户指定环境中由用户验证，自动化检查只使用合成数据与回环服务器。

本次排查不自行修改版本号或发布标签。

已完成的本地验证：189 项 Swift 测试、12 项注册探针检查、外部／本地输入保护的启动与取消及重复释放检查、最终应用与 DMG 签名及镜像校验。生命周期检查未请求新的系统权限，没有生成按键或连接真实 FTP。版本仍为 0.2.1 的本地验收产物不代表已经发布或替换当前安装版；修复版的 IDEA 实际复制验收留到用户指定版本后的安装阶段。
