# 构建、发布与更新

## 当前状态

源码和 Release 均保留在私有仓库 `DB-XiaoQiang/shanchuan`。下载需要登录且拥有权限。按当前决定，客户端更新源暂不配置，不嵌入 GitHub 令牌，不更改仓库可见性。

`VERSION` 是两个平台唯一的版本来源，格式为 `x.y.z`。主分支提交、PR 和手动运行触发“双端构建与测试”：

- macOS：Swift 测试、三组回环 FTP 集成测试、Release 编译、无签名 CI DMG 与 ZIP；镜像自动验证并只读挂载检查应用及 Applications 链接。
- Windows：Release 编译、核心测试、自包含便携 ZIP 和 Velopack 安装/更新包。

推送 `v<VERSION>` 标签触发“版本发布”，两端全部通过后创建 GitHub Release，附带 SHA256SUMS。macOS 未配置 Developer ID 签名和公证时，Release 自动保留为草稿；macOS 无签名包仅供测试，不保证 Gatekeeper 接受或辅助功能授权稳定。Windows 尚未配置 Authenticode 签名，可能出现系统信任提示。CI 不代替真实 FTP 和系统交互真机验收。

## 发布步骤

1. 修改 `VERSION`，提交并推送主分支，等待双端 CI 通过。
2. 创建并推送对应标签，如 `git tag v0.2.0`、`git push origin v0.2.0`。
3. 查看自动生成的 Release 草稿和附件，按验收结果正式发布。

失败后可以在 Actions 手动运行“版本发布”，填写已有标签。已有 Release 时工作流拒绝覆盖；已发行版本的修复使用新版本号和新标签。

## macOS 安装包

每次打包同时生成 `Shanchuan-macos-arm64.dmg` 与 `Shanchuan-macos-arm64.zip`，GitHub 构建产物和版本 Release 均包含这两种格式，SHA256SUMS 同时覆盖两者。DMG 为压缩只读 HFS+ 镜像，内含“闪传.app”、Applications 链接和中文安装说明。

双击 DMG，将闪传拖到 Applications（应用程序），复制完成后推出镜像，再从应用程序启动。升级前等待传输完成并退出闪传。ZIP 继续作为 Sparkle 更新包，现有更新源格式不变。

打包会校验镜像完整性，再以不打开 Finder 的方式只读挂载检查内容，随后卸载；签名构建还验证镜像及内部应用签名。配置正式公证后，应用和 DMG 均会提交公证、装订并验证票据。普通本地构建仍使用已有开发证书；CI 未配置正式证书时仍只生成测试包，DMG 格式本身不会改变系统信任状态。

## macOS 正式签名配置

在 GitHub Actions secrets 中设置：

| 名称 | 内容 |
| --- | --- |
| `MACOS_CERTIFICATE_P12` | Developer ID Application 证书及私钥的 P12，base64 编码 |
| `MACOS_CERTIFICATE_PASSWORD` | P12 密码 |
| `APPLE_ID` | 公证账户 |
| `APPLE_TEAM_ID` | 开发者 Team ID |
| `APPLE_APP_PASSWORD` | Apple 应用专用密码 |

临时钥匙串仅在发布任务中创建，结束删除。无证书时显式生成无签名测试包；提供不完整或无效证书时失败，不静默降级。Bundle ID 保持 `local.copytool.independent`。从开发签名切换正式签名时，应真机验证辅助功能和钥匙串访问，必要时重新授权。

## macOS 应用更新（更新源待配置）

已接入 Sparkle 2.10.1，提供“检查更新…”。仅当包内同时存在更新源地址和 Ed25519 公钥时，启动自动检查。未配置时提示手动下载，不发起更新请求。更新重启遇到发送队列时，延迟至队列完成。

启用时设置 Actions variables：

| 名称 | 内容 |
| --- | --- |
| `MACOS_UPDATE_FEED` | 客户端可访问的 HTTPS appcast.xml 地址 |
| `MACOS_DOWNLOAD_BASE` | 当前版本 ZIP 所在的 HTTPS 目录，每次发行随版本更新 |
| `SPARKLE_PUBLIC_KEY` | Sparkle 公钥 |

另设置 secret `SPARKLE_PRIVATE_KEY`，内容为 Sparkle `generate_keys` 导出的私钥。发布任务用 Sparkle 工具对公证后的 ZIP 签名，生成 appcast.xml 附件。需将 feed 和 ZIP 同步到配置的更新服务器，当前工作流不会部署外部服务器。启用 feed 时必须有正式签名及公证。

私有 GitHub Release 不能直接作为匿名客户端更新源。后续确定可访问的更新服务器或发布仓库；不要将个人 GitHub 令牌写入应用。

## Windows 应用更新（更新源待配置）

已接入 Velopack 1.2.161，产物包含 Setup、完整更新包、更新索引和便携 ZIP。第一次用 Setup 安装；旧版解压单文件 EXE 保留手动升级路径。

未来设置 variable `WINDOWS_UPDATE_REPOSITORY` 为客户端可匿名访问的 GitHub 发布仓库 HTTPS URL，该地址编入正式版本。目标仓库需包含相同版本 Velopack 附件；当前工作流只发布源码仓库，不自动镜像。留空时不发起更新检查。

已安装版本启动时检查更新，有新版本时询问是否下载，也可手动检查。Velopack 验证下载完整性，更新在用户退出并重新启动时安装，不强制结束 FTP。数据仍位于 `%APPDATA%\Shanchuan`，不随安装目录替换。内网无法访问 GitHub 时使用离线 Setup；内网更新源接入留待后续配置。

## 启用前验收

使用两个连续版本验证检查、下载、错误网络、不可用源、包校验失败、传输期间不退出、重启安装、配置/密码/历史保留、单实例和快捷键恢复。macOS 还需验证签名、公证和系统权限；Windows 需在 Windows 10/11 验证 Setup 安装和卸载。
