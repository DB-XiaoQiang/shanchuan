# 闪传 Windows 版

基于现有闪传的独立 Windows 实现，目标系统为 Windows 10/11。技术栈为 C#、.NET 8、WPF 和 FluentFTP；不读取或修改原 macOS 应用的数据。

## 已实现

- 明确的网络位置配置：内网只接收（允许 FTP 下载、删除，禁止上传）；外网只发送（允许 FTP 上传，禁止下载和删除）；未设置时发送和接收均禁用。不会根据 IP 地址自动判断。
- 外网默认 `Ctrl+Alt+C` 复制选中文本、图片或文件，生成本地记录并加入 FTP 发送队列；`Ctrl+Alt+V` 只粘贴。
- 不监听后台剪贴板变化，Windows 原生 `Ctrl+C` 不进入闪传历史，也不上传。
- 内网按配置间隔轮询外网投递，支持 UTF-8 文本、普通文件和文件夹；接收成功后写入 Windows 剪贴板并生成“已接收”历史。文件和文件夹同时保存到接收目录，同名内容不覆盖。
- 下载后验证 MD5，再提交本地文件并清理远端；非法清单、校验失败或安全路径检查失败不会删除远端数据。远端删除失败会记录警告并在后续检查中重试清理。
- 主窗口与配置中心持续显示网络位置、最近接收检查时间和结果；发送队列与核心 FTP 服务执行双层权限检查。
- 文件多选、文件夹选择、拖放发送、历史重发、删除、清空、搜索、类型筛选和隐私模式。
- 文件夹发送前打包 ZIP；目录排除支持名称、相对路径、`*`、`?`、`**` 和末尾 `/` 的目录限定。接收 ZIP 会拒绝绝对路径、路径穿越和符号链接。
- FTP 配置自动保存；测试连接只验证登录和目标目录访问，不上传、创建或删除服务器文件；连接与读取超时各为 5 秒，总时限为 10 秒，不提供额外取消按钮。
- 串行传输队列、取消当前任务并清空等待队列、按真实字节加权的进度，以及右上角进度卡片。
- 持久化传输日志、Windows 托盘、单实例运行和可选登录启动。
- FTP 密码保存在当前用户的 Windows 凭据管理器，目标名称为 `Shanchuan/FTP`，不写入 JSON 配置。
- 沿用现有闪传 Logo，并提供 Windows 图标。

## 首次配置与内外网使用

1. 在外网电脑的“配置中心 → 网络位置”选择“外网（只发送）”，填写 FTP 服务器、账号和目标目录。
2. 在内网 Windows 11 电脑选择“内网（只接收）”，填写同一服务器和目标目录，并设置接收目录。接收目录留空时默认为当前用户的 `Downloads\Shanchuan`。
3. 内网检查间隔默认为 5 秒，可设为 2–3600 秒。主窗口会显示“内网 · 只接收”、最近检查时间及结果；失败原因同时写入传输日志。
4. 从旧版本升级的配置默认为“未设置”，必须手动选择位置后才能发送或接收。这是权限保护，不是连接故障。

FTP 账号还需由服务器正确授权：外网账号需要目标目录及 `system_temp` 的写入权限；内网账号需要该目录的列表、读取和删除权限。程序中的权限限制不能代替服务器 ACL，建议服务器端同时禁止内网上传、禁止外网下载和删除。

## 快捷键边界

自定义复制热键触发后，程序会等待修饰键松开，再向当前前台应用发送普通 `Ctrl+C`，读取这次新产生的剪贴板内容并投递。正常应用更新剪贴板后立即继续，最长等待 5 秒；不会因为没有新内容而发送旧剪贴板。内网和未设置模式不会模拟复制或加入发送队列，重复触发时不会并发读取剪贴板。

主窗口和配置中心持续显示全局快捷键注册状态及实际组合键。传输日志按“快捷键已触发 → 已捕获新剪贴板 → 加入发送队列 → FTP 发送结果”记录各阶段；剪贴板被占用、前方应用不响应 `Ctrl+C`、热键冲突和 FTP 失败会显示不同原因。

粘贴热键只发送普通 `Ctrl+V`。企业安全软件、远程桌面或目标应用的输入限制可能影响全局按键投递，需要在实际 Windows 环境验收。

## FTP 协议兼容

- 文本：UTF-8 内容直接写入 `<目录>/system_temp/<文本控制名>.<时间戳>`，接收端直接读取该控制文件。
- 普通文件：实体远端名去掉最后一个扩展名，控制清单仍记录原始文件名。
- Office 文件：保留扩展名；只有启用相应选项且文件前 6 字节为 `877D1C` 时，才路由到解密前缀目录，不执行解密；接收端按同一路由规则取回原始内容。
- 文件夹：实体为 ZIP，远端名不带 `.zip`；清单条目使用 `folder:<原始名称>|<MD5>`，接收端校验后解压到以该文件夹命名的本地目录。
- 文件实体全部上传后，最后上传 `file=<名称>|<MD5>...\r\n<时间戳>` 控制文件。接收端只处理 `<文本控制名>.<数字时间戳>` 控制文件，其他目录内容不处理。
- 当前版本实现 FTP，不包含 FTPS／SFTP。发送时符号链接和 Windows 联接点会被拒绝，避免意外打包链接目标；接收时 ZIP 符号链接也会被拒绝。

## 本机数据

配置、历史、图片缓存、接收状态和日志位于 `%APPDATA%\Shanchuan`：

- `settings.json`：网络位置、接收目录、服务器、快捷键等非敏感配置；不包含 FTP 密码。
- `history.json`、`Media/`：明确发送或成功接收的历史和图片。
- `receive-state.json`：有上限的已处理控制文件记录，以及删除失败后的待清理项；不包含 FTP 密码。
- `transfer-logs.json`：最多保留 1000 条结构化日志。

历史记录可能包含主动发送或接收的文本和路径；隐私模式只遮挡主界面，不清除或加密现有历史文件。

## 构建与测试

在 Windows 安装 .NET 8 SDK，然后在仓库根目录执行：

```powershell
dotnet restore windows/Shanchuan.sln
dotnet build windows/Shanchuan.sln --configuration Release
dotnet test windows/tests/Shanchuan.Core.Tests/Shanchuan.Core.Tests.csproj --configuration Release
powershell -ExecutionPolicy Bypass -File windows/scripts/publish.ps1 -Runtime win-x64
```

发布脚本会重新运行测试，生成自包含的单文件程序及 ZIP：

```text
windows/dist/publish/win-x64/Shanchuan.exe
windows/dist/Shanchuan-win-x64.zip
```

解压后运行 `Shanchuan.exe`，目标电脑无需另外安装 .NET 运行时。也可在 GitHub Actions 运行 **双端构建与测试** 工作流，下载 `Shanchuan-windows-x64` 构建产物。

## 验收边界

核心协议、接收下载与删除、权限拒绝、MD5 失败保留、ZIP 安全、排除规则、持久化和进度统计有跨平台自动化测试，FTP 自动化仅连接 `127.0.0.1` 回环服务器。WPF 工程支持编译检查，但 Windows 剪贴板、全局热键、真实按键投递、凭据管理器、托盘、安装后启动和实际内外网服务器权限仍需在 Windows 10/11 与目标 FTP 环境中验收。不要把“连接测试成功”视为接收端已经处理文件。

## 版本发布与应用更新

共用仓库根目录的 `VERSION`。v0.1.1 外网端每天本机时间 01:00 检查公开 GitHub 正式版，并在启动/唤醒后补查；下载并验签后经独立 FTP 更新目录自动转发。内网端只从 FTP 获取更新，共享包不被删除，不影响剪贴板或普通历史。

左下角显示当前版本、更新状态和投递状态；用户点击并确认后才将缓存交给 Velopack 安装，传输结束后再重启。第一次从旧版升级使用 Setup。本次 0.1.2 公开为预发布，仅供手动下载测试，正式更新通道不启用。稳定版缺少正式签名公证和发行签名时仍保留草稿。详见 [发布与更新](../docs/发布与更新.md)。
