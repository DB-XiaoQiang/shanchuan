# Windows 原生更新验收夹具

此工程仅供一次性的 GitHub Windows runner 验收，不编入用户版闪传，也不向公开更新通道上传夹具。

使用生产 `UpdateCoordinator`、签名验证、独立缓存及安装授权策略，结合真实 Velopack Setup 和 Update.exe 验证：

1. 构建明确指定的旧版本和目标版本，包 ID 沿用生产验证器固定的 `Shanchuan`，可执行文件则为独立的 `Shanchuan.UpdateSmoke.exe`。
2. Setup 静默安装到本次 `RUNNER_TEMP` 下的唯一目录；若已有正式闪传目录、进程或卸载登记则拒绝执行。
3. 用临时内存 P-256 私钥签署隔离目录中的完整包与索引。验证器只向这个进程注入测试公钥，生产公钥和信任配置不变。
4. 在未确认和错误授权时验证没有原生待安装包；测试驱动写入绑定版本及清单摘要的明确授权后才暂存和安装。
5. 真实 Update.exe 替换文件并重启夹具，检查新版本、新 PID、原始数据样例完整性。完成后只清理本次目录对应的进程与安装登记。

报告为 `$RUNNER_TEMP/native-update-smoke/report.json`，日志位于同级目录。私钥不落盘、不导出、不使用生产 Secrets；更新源为本地文件，不访问 GitHub Release 或 FTP。

此验收证明生产协调与授权逻辑及原生升级机制能运行，不声称已让已发布的旧版 GUI 通过关闭中的预发布通道自动升级。真正的 GUI 安装确认与公司目标环境仍需在该环境进行验收。
